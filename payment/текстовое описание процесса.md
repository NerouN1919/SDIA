# Текстовое описание процесса исполнения платежа

## Успешный кейс
Пользователь отпралвяет запрос на соврешние платежа. Запрос идет на Api Gateway, кто происходит аутентификация пользователя, процессы rate limitting, circuit breaker для запросов.  
Запрос перенаправляется на Orchestrator(Saga оркестрация), где определяется целевой сервис по CQRS. В данном случае - запрос на Wallet Service.  
Wallet Service достает из БД баланс пользователя, смотрит есть ли доступные средства для совершения операции. Средства доступны, значит происходит резервирование платежа в БД. Создается запись в outbox таблицу с эвентом PaymentInitiated(Outbox + хореография).
Пользователю возвращается ответ, что платеж создан.
Debezium считывает появившиеся записи из WAL журана outbox таблицы(CDC) и направляет их в Kafka.
Параллельно отдельным процессом читаются записиси PaymentInitiated из kafka сервисом Transaction Query Service(CQRS), где обновляются представления в ElasticSearch для оптимизированного чтения данных(eventual consistency).  
То же событие, PaymentInitiated, читает Transaction Service (CQRS для write модели + хореография). События проверяются на идемпотентность по idempotency-Key из payload по walletTransactionId.  
Отправляется запрос в Core Service для бух учета, он отдает положительный ответ, что все ОК. Отправляется запрос внешнему провайдеру на проведение платежа, возвращается ответ, включающий paymentId. Сохраняем весь ответ, включая paymentId.  
Callback Provider получает Callback запросы от провайдера сначала через Api Gateway, потом направляет в сам callback сервис. Валидируем ключи по HMAC. И отправляет прямым вызовом к Transaction Service ответ от провайдера.  
В Transaction Service обновляем статус платежа на успешный и создаем запись в outbox c типом PaymentResult(Outbox + хореография).
Debezium считывает появившиеся записи из WAL журана outbox таблицы(CDC) и направляет их в Kafka.
В wallet service параллельно вычитываем Payment Result события и проверяем консистентность по transaction_id. Окончально подтверждаем резервирование средств. Создаем записи в outbox c типами PaymentCompleted и NotificationSent(Outbox + хореография).  
Debezium считывает появившиеся записи из WAL журана outbox таблицы(CDC) и направляет их в Kafka.  
Notification Service вычитывает записи из kafka с типом NotificationSent, проверяет консистентность по wallet_transacion.id и отправляет уведомление пользователю о подтверждении платежа.  
Параллельно Transaction Query Service(CQRS) читает из Kafka события PaymentCompleted и обновляет свою read модель представления.

Debezium считывает появившиеся записи из WAL журана outbox таблицы(CDC) и направляет их в Kafka.
