# Деплой

Для деплоя используется Canary Deployments. Всего имеется 4 statble поды.  
Этапы Canary:
- 10%
- 50%
- 100%

Переходы между эатапамы происходит по проверке SLI. После каждого увеличения количества canary подов и распределения нагрузки в API Gateway ждём 5 минут, чтобы нагрузка прошла на поды и было по чему замерять SLI  
Проверкой SLI как раз занимется Rollout, который делает запросы в Prometheus. Также он обновляет параметры балансировки в API Gateway  
Если SLO оказались неудовлетворительными, то запускается механизм rollback, то есть мы выставляем stable pods в 100%, а canary pods в 0% и возвращаем балансировку API Gateway в исходное состояние  
Чтобы при деплое или откате пользователи не получали ошибки, мы устанавливаем задержку, чтобы API Gateway успел убрать под из маршрутизации. Под не попадёт также в балансировщик readiness проба не будет готова, то есть приложение не начнет откликать на запросы жизнеспособности. Тем самым пользователи всегда стучатся в рабочеспособную поду
