| Поток / сценарий | Брокер (Kafka / RabbitMQ / нет) | Тип сообщений (event / command / job) | Обоснование выбора |
|---|---|---|---|
| Payment → Merchant Callback | Kafka | Event | Ожидается большое количество сообщений, что делает Kafka более производительной, чем Rabbit. Kafka сохраняет сообщения во внутренний лог и повторная вычитка сообщений. Последовательность данных не требуется |
| Payment → Antifraud | Kafka | Event | Ожидается большое количество сообщений, что делает Kafka производительнее Rabbit, поддерживает лог сообщений и ретраи в частных случаях. Последовательность данных не требуется |
| Payment → Notification | RabbitMQ | Event | Лог сообщений не требуется. В дальнейшем для добавления sms и push уведомлений есть возможность добавить приоритетные очереди. Push доставка больше подходит под концепцию |
